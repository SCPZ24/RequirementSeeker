# 项目状态

本文记录仓库中可验证的开发范围与集成边界。远端分支、PR 和审查状态以 GitHub 当前页面为准，不在本文保存易过期的网络快照。

## 当前里程碑

当前交付目标是一个可独立验证、可由产品主工程接入的 Agent 模块。M0 已建立 Python 包、输入输出契约、JSON Schema、合成测试样本和离线校验命令，为后续业务规则与模型适配提供稳定边界。

M0 是契约基础，不代表 Agent 功能已经完成，也不满足完整产品的 H0/H1 验收条件。详细证据与限制见 [M0 验收记录](development/2026-09-05-m0-acceptance.md)。

## 已交付范围

- `packages/agent` 独立 Python 3.12 包及锁文件。
- `analysis-request.v1` 与 `analysis-result.v1` Pydantic 契约和 JSON Schema。
- 请求、结果及跨对象关系的离线校验命令。
- 30 个契约样本和 10 个合成业务评测种子。
- 契约测试、静态检查、类型检查和独立安装验证入口。
- Agent 契约、架构决策、安装说明、评审记录和阶段性交付计划。

## 尚未交付范围

- M1 预处理、可信请求与证据核验、作者排除和跨日业务规则。
- 语义聚类、模型网关、多模态升级、预算结算、缓存与重放。
- 真实采集数据、持久化、任务调度、CLI/Web 产品集成。
- 真实模型评测、macOS 验证和仓库 CI。

当前校验可以证明结构和部分对象关系符合 v1 契约，不能证明证据真实性、业务准入有效性或模型输出质量。

## 集成顺序

1. 先审查并合并 Agent 设计与需求一致性文档，作为 M0 的文档依赖。
2. 将 M0 作为独立变更审查，确认 Python 包边界、v1 契约和上游接入方式。
3. 在契约获确认后推进 M1；后续里程碑及退出条件见 [Agent 交付计划](development/2026-09-05-agent-delivery-plan.md)。
4. 采集、数据库、任务系统和页面实现接入前，解决 [开放问题](OPEN_QUESTIONS.md) 中对应阶段的阻塞项。

模块采用的默认值记录在 [ADR-001](architecture/ADR-001-agent-foundation.md)，这些默认值只用于保持 Agent 开发可推进，不表示完整产品架构已经获批。

## 验证入口

环境安装、测试、静态检查、Schema 导出和样本校验命令见 [Agent 安装与开发说明](development/agent-setup.md)。评审时应从干净环境重新运行这些命令，并同时核对 M0 验收记录中的已知限制。
