## 分阶段实施门槛（2026-09-05 更新）

协作安排已改为你先完成 Agent 模块、发起者随后接入。原“全部 P0 关闭后才能规划”的规则由以下阶段门槛替代；这不表示以下未决事项已获得答案。

1. **契约与纯规则：** 依据现有 Agent 边界先开展 M0/M1；在模块内确定语言、目录、测试框架、输入输出版本、作者/视频语义和合成 fixture，不等待前端、数据库、Tag 或真实采集账号。
2. **模型能力实现：** 在 M2/M3 前补齐相关样本、评测方案、预算、缓存、有限重试和上下文策略。实际模型配置缺失时可验证替身流程，但真实模型验收保持未完成。
3. **去重与可接入交付：** 在 M4/M5 前明确输出所有权、幂等与恢复协议、证据保留、匿名化和接入示例。Agent 契约由模块负责人维护，宿主接入时共同核对。
4. **项目联调：** 在 M6 解决全栈技术、进程拓扑、真实采集 fixture、事务存储、媒体生产责任和系统级恢复等剩余依赖。
5. **完成标记：** 离线可接入交付 H0 与真实模型/目标环境验证完成 H1 分别记录；具体定义及问题映射见当前交付计划。

现有问题的负责人和原关闭条件继续用于项目级追踪。某项不阻塞当前阶段，不代表该问题已关闭。最终技术版本和可执行命令随实际工程配置补全并验证。
