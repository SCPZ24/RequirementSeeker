# RequirementSeeker 开发前开放问题清单

- 状态：供项目发起者与 Agent 模块负责人共同确认
- 建立日期：2026-09-04
- 适用范围：MVP 开发准备与 Agent 模块实施计划
- 事实来源优先级：`docs/PRD.md` → `docs/Pages.md` → `docs/design.md`

## 使用规则

1. 只有已经获得明确答案并写入对应正式文档的问题才能勾选。
2. 聊天、口头会议和临时截图中的结论应转写到仓库文档后再视为已关闭。
3. P0 问题关闭前，不生成精确到文件和测试命令的最终实施计划。
4. Tag 模块处于暂停状态，不得用本清单中的技术决定变相固化旧 Tag 方案。

## P0：最终实施计划的阻塞问题

### 项目现状与技术底座

- [ ] P0-001：是否存在尚未推送的代码、其他开发分支、Figma、数据库草图、接口样例或外部设计文档？
  - 负责人：项目发起者
  - 关闭条件：在 `docs/PROJECT_STATUS.md` 中列出全部现有资产、完成项、进行中工作和下一里程碑。

- [ ] P0-002：后端、前端、数据库、包管理、ORM、迁移、测试、格式化、Lint 和类型检查分别采用什么技术与版本？
  - 负责人：项目发起者最终批准，双方共同提案
  - 关闭条件：形成 `docs/architecture/ADR-001-tech-stack.md`，包含 macOS 支持版本和安装方式。

- [ ] P0-003：CLI、调度器、BettaFish 适配器、Agent、持久化、Web API 和前端运行在同一进程、子进程还是多个本地服务中？
  - 负责人：双方
  - 关闭条件：形成 `docs/architecture/overview.md`，明确进程、调用方向、事务边界和失败传播。

- [ ] P0-004：每个模块的实现负责人、接口批准人和联调负责人是谁？
  - 负责人：项目发起者
  - 关闭条件：形成 `docs/OWNERSHIP.md`，特别标明 OCR、关键帧、数据库、任务编排、向量检索和 CI 的归属。

### 外部接口与数据所有权

- [ ] P0-005：BettaFish、MindSpider 和 MediaCrawler 以源码依赖、子进程还是内部服务方式接入？
  - 负责人：采集负责人/项目发起者
  - 关闭条件：`docs/contracts/crawler-agent-contract.md` 包含集成方式、脱敏 JSON fixture、稳定 ID、回复关系、时间格式和错误格式。

- [ ] P0-006：视频下载、字幕获取、语音转写、关键帧抽取和 OCR 分别由采集层还是 Agent 层负责？
  - 负责人：双方
  - 关闭条件：输入契约能够明确区分原始媒体引用与已经提取的文本/帧结果。

- [ ] P0-007：Agent 输出 Schema 与数据库模型由谁拥有，破坏性字段变更如何版本化？
  - 负责人：双方
  - 关闭条件：形成 `docs/contracts/agent-schemas.md`，并明确 Agent 生成字段与后端生成字段。

### 模型、嵌入和协议

- [ ] P0-008：PRD 的“单一模型”是否允许额外使用嵌入模型？
  - 负责人：项目发起者
  - 风险：向量数据库通常依赖独立嵌入模型，可能与 FR-19 冲突。
  - 关闭条件：明确允许独立嵌入模型、使用同一模型能力，或 MVP 禁止向量嵌入三者之一。

- [ ] P0-009：通话记录中的 ACP 全称和目标是什么，是否指已有标准，是否属于 MVP？
  - 负责人：项目发起者
  - 默认建议：若仅为管线步骤传递上下文，使用版本化 `AgentContext`；通用多 Agent 通信协议不进入 MVP。
  - 关闭条件：形成独立 ADR，说明参与者、传输边界、持久化和与 MCP 的关系。

- [ ] P0-010：实际使用哪个 OpenAI 兼容模型，其文本、图像、结构化输出、Token 统计和最大上下文能力是什么？
  - 负责人：项目发起者
  - 关闭条件：提供不含密钥的模型能力配置样例和能力检测预期结果。

### 状态和恢复

- [ ] P0-011：放弃和决定开发的“不可恢复”是只限制 UI，还是数据库层也不提供纠错入口？
  - 负责人：项目发起者
  - 关闭条件：生命周期状态机明确普通操作、纠错操作和审计要求。

- [ ] P0-012：失败重试以平台、视频、评论批次还是单个 Agent 步骤为最小恢复单位？
  - 负责人：双方
  - 关闭条件：形成运行检查点、幂等键、版本冻结和部分提交策略。

- [ ] P1-004：规定有争议样本的标注和裁决流程。
- [ ] P1-005：规定模型或提示词升级时必须通过的回归门槛。

### Token Harness

- [ ] P1-006：确定每次运行、每视频、每批次的 Token 或调用预算。
- [ ] P1-007：确定批次按 Token 还是评论数量划分，以及跨批次簇的合并方式。
- [ ] P1-008：确定缓存键组成、缓存保留期和提示词/Schema 升级后的失效规则。
- [ ] P1-009：确定结构化输出修复次数、网络重试次数和退避策略。
- [ ] P1-010：确定预算耗尽、上下文不足、模型失败和取消的不同结果状态。

### 多模态与去重

- [ ] P1-011：确定字幕、语音转写、OCR、关键帧和视觉模型的具体升级顺序。
- [ ] P1-012：确定 OCR 工具、语言范围、帧数、文件大小和中间文件保留限制。
- [ ] P1-013：确定语义检索只负责候选召回还是允许自动合并机会。
- [ ] P1-014：确定相似度阈值的校准方式及嵌入模型变更后的重建策略。
- [ ] P1-015：确定错误合并的解除流程及原始证据关系保留方式。

### 数据与安全

- [ ] P1-016：确定作者匿名哈希的输入、作用域、盐或密钥管理方式。
- [ ] P1-017：确定真实评论能否进入公开测试 fixture，以及匿名化标准。
- [ ] P1-018：规定社媒评论、字幕、OCR 和模型输出的提示注入防护与展示转义。
- [ ] P1-019：规定远程媒体 URL、文件大小、类型和本地路径的安全校验。
- [ ] P1-020：完成 BettaFish、MindSpider、MediaCrawler 及新增 OCR/向量依赖的许可证兼容审查。

## 实施计划生成门槛

生成精确到任务、文件和测试命令的 Agent 实施计划前，至少需要：

1. 所有 P0 问题关闭；
2. P1-001 至 P1-010 有明确方案；
3. 确定代码目录与测试框架；
4. 获得一份采集输入 fixture；
5. 获得项目发起者对 Agent 输入/输出边界的确认。
