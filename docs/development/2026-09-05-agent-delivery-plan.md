# Agent 模块后续开发与交接计划

- 日期：2026-09-05。
- 状态：M0 工程底座、契约与样本已完成；M1–M6 尚未执行，详见 [M0 验收记录](2026-09-05-m0-acceptance.md)。
- 依据：[项目状态](../PROJECT_STATUS.md)、[审查报告](../reviews/2026-09-05-project-review.md)、[Agent 设计](../superpowers/specs/2026-09-04-agent-module-design.md)。
- 本文的工程默认值是可审查的提案，不冒充发起者已经确认的全栈架构。

## 1. 交付目标

你先交付一个可独立安装和验证的 Agent 模块：输入标准化视频与评论，输出需求簇、确定性共识结论、上下文决策、软件机会候选、去重决策、推断链和审计元数据。发起者拿到模块、契约、示例和验收报告后，实现采集、数据库、调度和界面接入。

**模块交付不以整站完成、平台登录成功或 Tag 重设计完成为前提。真实模型验证与离线替身验证分别记录。**

| 责任 | 你先完成 | 发起者后续接入 |
|---|---|---|
| 输入输出 | 版本化契约、校验、样本、兼容策略 | 将采集和业务数据映射到契约 |
| 分析 | 预处理、信号识别、聚类、共识、机会过滤、去重决策 | 提供业务验收反馈 |
| 多模态 | 触发规则、上下文请求、结果校验、能力不足行为 | 媒体获取、字幕/音频/帧/OCR 的生产适配器 |
| 模型调用 | 单模型网关、结构化结果、有限重试、预算与审计 | 提供本地密钥配置与实际模型选择 |
| 状态和存储 | 提交意图、幂等键、状态协议、离线替身 | 正式 ID、事务、检查点、清理、备份 |
| 产品运行 | 离线 runner、评测和开发说明 | CLI、定时器、运行历史、Web API、前端 |

采集、存储和媒体生产的具体成员分配尚未公开；这里以“发起者后续接入”描述交接责任，不推断他会亲自实现每项。

## 2. 实现边界与默认方案

### 2.1 先作为独立库交付

建议用 Python 模块承载 Agent，模块内部采用类型化数据模型、Schema 校验和自动测试。工程初始化时核实 Python、依赖和工具版本后锁定；不在本次文档阶段随意指定未验证的版本。全栈后端不论采用何种技术，都应能通过版本化 JSON 契约接入。

默认先提供库调用与离线命令入口，不先搭建 HTTP 服务或通用 Agent 通信协议。若发起者已经有语言约定，应在工程初始化时适配；无此约定则可在模块内作可逆选择并记录 ADR，无需等待前端、数据库和 ORM 定稿。

目标布局（M0 已建立契约、测试和样本；domain/pipeline/ports/adapters/prompts 随后续能力建立，不提前放置空壳）：

```text
packages/agent/
  pyproject.toml
  src/requirementseeker_agent/
    contracts/       # 输入、输出、错误与版本
    domain/          # 确定性预处理、作者与证据约束
    pipeline/        # 信号、聚类、上下文、推导、去重
    ports/           # 模型、媒体、历史候选、分析状态接口
    adapters/        # 单模型适配与离线替身
    prompts/         # 版本化提示词
  tests/
    unit/
    contract/
    pipeline/
    fixtures/
  examples/
  evals/
```

模块安装、Lint、类型检查和测试命令已在 M0 建立真实配置后写入 [开发说明](agent-setup.md)；后续目录继续按实际能力建立。

### 2.2 不引入额外工程前置项

- Tag 不进入业务依赖；平台原生标签只是原始视频上下文。
- 首期不引入第二嵌入模型或向量数据库；历史去重先以本地召回策略加同一模型的结构化比较实现。召回不完整或预算不足时应返回待处理，不能据此断言“无重复”。
- ACP、MCP、通用多 Agent 框架不在当前范围。
- 不实现自动可行性研究、竞品分析、获客执行或人工阶段推进。
- 不要求真实平台账号才能跑核心测试；真实模型和平台验证采用明确的独立入口。

## 3. 首先冻结的模块契约

### 3.1 输入

建议定义 `AnalysisRequest v1`，至少包含：

| 类别 | 必要语义 |
|---|---|
| 运行 | Schema 版本、运行 ID、关联原运行、输入快照 ID/哈希、固定分析时间 |
| 版本 | 规则、提示词、模型配置与可获取的模型版本标识 |
| 视频 | 平台、稳定视频 ID、作者稳定 ID、标题、简介、来源链接 |
| 评论 | 平台、视频 ID、评论 ID、稳定作者 ID/缺失状态、父评论 ID、原文、采集时间、到期时间 |
| 历史 | 单视频十天有效评论快照；历史机会查询接口及其数据版本 |
| 媒体 | 已提取上下文或受控媒体引用、能力与来源信息；不用任意本地路径作为可信输入 |
| 控制 | 视频/评论/模型调用与 Token 预算、取消信号、重试策略引用 |

所有时间使用带时区的统一序列化格式，参与计算前归一化。保留期起点需在 M0 明确；建议按首次采集时刻计算，重复抓取不自动延期。此建议尚未替代 PRD 的十天规则。

v1 的评论集合定义为调用方组装的“当前仍有效快照”，不是仅当天新增的一批。Agent 还需校验逐条到期时间、重复记录和所属视频，防止错误调用方绕过约束。缺失稳定作者 ID 的评论可用于上下文，不计人数。

### 3.2 输出

保留已有设计的八类结果：`NeedSignal`、`NeedCluster`、`ConsensusDecision`、`ContextDecision`、`OpportunityCandidate`、`OpportunityMergeDecision`、`InferenceStep`、`ModelInvocationAudit`。另提供统一运行结果封装，避免调用方解析自由文本判断状态。

建议结果类别：新候选、追加证据建议、业务拒绝、上下文不足、可重试错误、不可重试错误、预算受控结束、已取消。最终枚举和 JSON 字段在 M0 冻结；运行汇总状态由后端根据视频及平台结果生成，不直接复用单视频状态。

正式候选必须包含同一视频的至少三条可定位评论和三个不同有效作者；证据引文从输入记录提取，不能相信模型自己返回的作者人数或原文。模型提出的任何引用都必须属于当前输入集合。

输出还应具备：步骤和失败原因、是否可重试、用量是否可获得、已完成部分、证据引用、提交幂等键。Agent 生成候选标识和分析标识；后端生成正式机会 ID、生命周期、创建/更新提交时间，维护人工资料。

### 3.3 外部接口与所有权

| 接口 | Agent 所需能力 | 模块验收替身 | 生产责任 |
|---|---|---|---|
| ModelGateway | 按单模型配置执行文本/图像结构化调用 | 固定输出、坏输出、超时、usage 缺失 | Agent 提供适配，宿主注入配置 |
| MediaContextProvider | 按需返回上下文、缺失或失败 | 字幕/帧引用样本与不支持状态 | 采集/媒体层 |
| OpportunityHistory | 查询既有候选与来源关系 | 固定历史集合、分页及不完整标记 | 持久化层 |
| AnalysisStateStore | 重放已验证步骤结果、读取版本和过期状态 | 内存/临时本地实现 | 后端存储 |
| Commit sink | 接收候选或追加证据意图，幂等提交并确认 | 重复提交与失败模拟 | 后端事务层 |

分析成功与正式入库成功分别表示。只有宿主提交成功，才能计入正式新增机会数。分析重试不会覆盖用户备注或人工阶段。单纯的测试替身不作为生产存储交付。

### 3.4 稳定重放与数据保留

分析键应涵盖规范化输入快照、规则、提示词、Schema、模型配置与影响决策的历史版本；随机运行 ID 不应使相同逻辑工作失去幂等性。追加证据键还需包含目标机会和规范化证据集合，不能简单使用运行 ID。

同一有效分析键重用已校验语义结果；新版本单独分析并留下关联。含原文或可还原原文的缓存不得超过相关材料的到期时间。永久审计只保留允许的元数据；正式机会的证据单独形成受保护快照。

## 4. 按顺序推进的里程碑

### M0：工程底座、契约与样本

**进度：** 已完成并验证。工程决定见 [ADR-001](../architecture/ADR-001-agent-foundation.md)，交付证据见 [M0 验收记录](2026-09-05-m0-acceptance.md)。

**前提：** 本文的 Agent 范围与已有模块设计一致；无需先确定全站架构。

**工作：** 建立独立包、锁定工具链、定义输入/输出 Schema 和错误；记录语言选择、保留期起点、重放语义与有限预算策略；创建合成金标样本与测试框架；补齐敏感配置忽略规则及无密钥配置样例。

**交付：** 模块工程、契约文档、正反例 JSON、离线执行说明、模块 ADR。

**通过条件：** 无模型 Key、无平台登录时能安装并校验所有样本；坏输入有明确失败原因；Schema 与示例一致。采集真实 fixture 可以后补，但不能声称已验证真实采集兼容性。

### M1：确定性规则与跨日状态

**工作：** 实现评论去重、作者排除、视频隔离、证据引用校验、三人门槛；用时钟和存储替身验证有效期内增量快照和重放。

**交付：** 可独立调用的规则模块、边界测试、规则版本。

**通过条件：** 三条同作者评论不通过；缺失作者、视频作者自己、跨视频拼接均不通过；同视频有效期内“2 + 1”通过；过期数据不用于新准入。先以显式簇样本验证规则，此时不宣称已经实现语义识别。

### M2：模型网关、需求信号与聚类

**工作：** 建立单模型适配、能力检测、Schema 校验、有限修复/重试、预算、用量审计、缓存；实现需求信号提取和同视频聚类。批次拆分不能让同视频跨批次的有效簇遗漏，也不能重复计数。

**交付：** 版本化提示词、模型网关、可用假模型驱动的分析链、真实模型能力检测与评测入口。

**通过条件：** 超时、限流、坏 JSON、伪造证据引用、取消、预算用尽不会生成不完整机会；重试均计入预算；usage 未返回时明确未知。真实模型可用时，单独记录语义指标与能力检测结果。

### M3：上下文补充与机会过滤

**工作：** 在三人信号成立但对象不明时请求额外上下文；以补充内容复核语义；推导软件形态、非重运营理由和具体首批用户来源。

**交付：** 上下文接口、文本充分/不足/能力缺失的流程、机会候选与过滤理由。

**通过条件：** 文本充分不调用多模态；无视觉能力且对象不明时保持上下文不足；补充上下文后不再支持共识的簇不得生成机会；纯泛化获客建议和重人工服务方案被拒绝。媒体生产适配器尚未接入时，注明该部分只验证了协议替身。

### M4：去重、输出、重试与证据包

**工作：** 从历史机会召回候选，判断同一问题和解法方向，生成合并/新建意图；输出动态事实/推断节点及分层审计；完成幂等、取消和失败重试协议。

**交付：** 完整分析入口、历史及存储替身、端到端离线样本、结构化结果文件、错误案例。

**通过条件：** 同样证据重复提交不新增机会或来源；相同关键词但用户/场景不同不误合并；来源关系保留；原失败运行不改写；过期清理模拟不损坏正式证据；不覆盖人工字段。

### M5：模块验收与交接

**工作：** 跑完离线测试、固定金标评测和故障用例，完成安装/调用/配置/错误文档；用 Windows 和 macOS 验证核心包；整理交接清单与 PR。

**交付：** 安装包或可安装源码、锁定依赖、契约、样本、运行命令、评测报告、已知限制、接入责任表。

**两种完成标记：**

- H0「可接入」：离线规则、契约、假模型全流程和交接资料通过。真实模型或 macOS 未验证项必须显式列出。
- H1「Agent 模块完成」：在 H0 基础上，真实指定模型通过预先约定的语义评测和文本/图像能力降级测试，Windows/macOS 核心验证完成；不要求采集器或整站已完成。

若缺实际模型配置，只能交付 H0，不能用假模型测试替代 H1。发起者可在 H0 开始适配，模型验证作为明确剩余事项继续完成。

### M6：发起者接入，双方联调

在模块交付后，发起者依次接入标准化采集输入、历史和事务存储、任务锁/检查点/清理、API/CLI/页面。你负责契约问题和 Agent 缺陷修复。

实际采集 fixture、后端进程拓扑、全局运行重试、许可证核查和真实十天清理在这一阶段落实。先用固定输入完成真实后端联调，再用受预算限制的真实平台样本验证。Tag 继续独立等待设计，不得作为完成现有离线链路的前置条件。

## 5. 核心验收矩阵

| 用例 | 预期 | 阶段 |
|---|---|---|
| 同视频三位有效作者表达同一需求 | 共识通过，证据完整 | M1/M2 |
| 两位作者、多评论同作者、视频作者、作者 ID 缺失 | 不可凑足人数 | M1 |
| 三位作者来自多个视频 | 不通过 | M1 |
| 十天内两人后新增一人；旧记录已到期 | 前者可通过，后者不复用过期正文 | M1 |
| 纯表情、广告、无意义附和、语义有争议 | 不计入有效共识 | M2 |
| 模型引用不存在的评论或篡改原文 | 校验拒绝 | M2 |
| 评论/字幕要求忽略规则或泄露配置 | 作为不可信内容，不能改变门槛或产生工具动作 | M2/M3 |
| 文本充分；文本不足且不支持视觉 | 前者不升级，后者上下文不足 | M3 |
| 纸质流程可软件化；重人工交付；泛化获客描述 | 首者可继续，后两者过滤 | M3 |
| 重复机会；词汇近似但场景不同 | 追加证据；保留独立机会 | M4 |
| 模型错误/取消/预算结束/真正零结果 | 状态可区分，不误记成功或新增机会 | M2/M4 |
| 同一输入重放；模型/规则版本更新 | 复用已验证结果；新分析不覆写历史 | M4 |
| 十天清理；永久审计；正式证据 | 普通原文删除，审计不泄漏，正式证据可读 | M4/M6 |
| Windows 开发、macOS 安装与执行 | 核心包均可运行；系统调度另由宿主验收 | M5/M6 |

规则和契约的不变量用例必须全部通过。真实语义评测至少报告精确率、召回率、机会误报、误合并、上下文不足、用量与失败率，并列出样本量及逐例错误。数值门槛在 M2 联网评测前登记；尚无共同认可的阈值时，不虚构“达标”。

## 7. 分支与交接方式

规划与 M0 实现已从 `docs/preimplementation-audit` 建立到 `codex/agent-core`，使后续代码不继续堆入原文档分支。若 PR #1 尚未合并，后续代码 PR 需明确基线依赖；文档合并后再调整代码 PR 基线，不要求自行合并主分支。

你已是协作者，可使用发起者仓库的功能分支协作，也可延续已有 fork。现有远端配置不会因为身份变化自动改变。当前 `gh` 认证和 Git 连接问题在首次推送前解决即可，不阻塞本地开发。

交接包逐项检查：

- [ ] 能在无平台登录情况下安装并跑离线演示。
- [ ] 有输入/输出 Schema、正常与失败样本、契约版本策略。
- [ ] 所有固定业务规则有测试，真实模型评测单独给出结果。
- [ ] 明确 H0/H1 状态和实际运行环境，不隐去未验证项。
- [ ] 记录预算、重试、缓存、取消、错误和 Token 统计语义。
- [ ] 标出采集、媒体、存储、调度和前端的具体接入点。
