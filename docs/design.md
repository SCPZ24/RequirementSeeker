# RequirementSeeker · Stamen Atlas 设计系统

- 文档状态：最终定稿
- 版本：MVP Design System v1
- 日期：2026-07-28
- 目标设备：用户个人 Mac 上的桌面浏览器
- 产品访问范围：仅 `localhost`
- 关联需求文档：`docs/PRD.md`
- 关联页面文档：`docs/Pages.md`

## 1. 文档用途

本文档定义 RequirementSeeker MVP 的最终视觉语言、设计令牌、组件规则和跨页面应用原则，是后续前端实现的稳定设计契约。

本文档只规定界面如何表达已经确认的产品功能，不增加或修改业务需求。页面职责、路由、字段、状态和交互以 `docs/Pages.md` 为准；业务范围与数据规则以 `docs/PRD.md` 为准。

当前不绑定 React、Vue、Svelte、CSS Modules、Tailwind 或其他前端技术。命名令牌可以映射到任意实现方式，但视觉语义和约束不得被框架默认样式替代。

Tag 模块仍未完成需求与页面设计。本文档不定义 Tag 页面、Tag 筛选器、Tag 状态或 Tag 专属组件。

## 2. 最终视觉方向

### 2.1 名称

最终视觉方向为 **Stamen Atlas**。

“Atlas”不是要求界面模拟一张地图，而是将需求发现理解为对未知问题空间的勘测：

1. 原始内容和评论是观测点。
2. Agent 的分析过程是勘测路径。
3. 软件机会是由事实逐步推导出的地形结论。
4. 孵化阶段是用户对机会进行人工验证的工作记录。

地图隐喻只用于组织信息、建立连续关系和区分层级，不作为装饰主题反复出现。

### 2.2 视觉气质

界面的整体气质固定为：

- 安静；
- 克制；
- 专业；
- 有研究与档案感；
- 适合长时间阅读；
- 具有辨识度，但不抢夺内容注意力。

界面不能呈现为营销网站、经营驾驶舱、通用企业后台或面向初学者的教学工具。

### 2.3 核心原则

1. **内容先于装饰。** Agent 的分析、证据、推断依据和过滤理由必须完整展示。
2. **事实与推断分离。** 事实节点和 AI 推断节点必须具有明确文字标签，不能只靠颜色区分。
3. **路径表达关系。** 细线、锚点和空间顺序用于表达推断关系，而不是为了营造“科技感”。
4. **赭石只标记重点。** 主要动作、关键路径和分析转折使用赭石；普通信息不滥用强调色。
5. **容器保持诚实。** 只有独立对象、层级或可点击区域才使用容器，不把每段文字包装成卡片。
6. **状态高于隐喻。** 在孵化、运行和设置页面中，阶段、错误、完成条件和可执行操作必须比地图隐喻更清楚。
7. **UI 文案保持简短。** 界面不重复解释显而易见的操作，不使用鼓励语、拟人化问候和填充式副标题。

### 2.4 明确禁止

以下视觉与文案模式禁止进入正式界面：

- 规则同心圆；
- CSS 径向渐变；
- 以固定圆心向外扩散的地图纹理；
- 等间距、等曲率复制的装饰曲线；
- 蓝紫色 AI 渐变和发光光晕；
- 大面积玻璃拟态；
- 大圆角通用 SaaS 卡片；
- 每个标题旁都放装饰图标；
- 无业务含义的状态圆点和统计数字；
- 为了“显得智能”添加的机器人、星光和魔法棒符号；
- 左右交接、蛇形摆动的推断链；
- 沿纵向路径连续向下指的方向箭头；
- 教学式废话、鼓励语和面向小学生的重复解释；
- 为了版面整洁截断 Agent 分析或代表评论。

## 3. 设计令牌

### 3.1 命名规则

设计令牌统一使用 `--rs-` 前缀。令牌名称描述语义，不描述具体页面或当前颜色。

例如：

- 使用 `--rs-color-action`；
- 不使用 `--rs-color-opportunity-detail-orange`。

实现可以把这些名称映射到框架变量、主题对象或 CSS 自定义属性，但不得改变令牌的语义。

### 3.2 颜色

| 令牌 | 值 | 用途 |
|---|---:|---|
| `--rs-color-paper` | `#E9E4DA` | 页面主背景、圆形锚点填充 |
| `--rs-color-surface` | `rgba(247, 244, 237, 0.88)` | 内容面板、阶段笔记和抬升表面 |
| `--rs-color-ink` | `#243B48` | 页面标题、主要文字、导航背景 |
| `--rs-color-body` | `#4C605E` | 正文、Agent 分析、说明文字 |
| `--rs-color-muted` | `#6B7974` | 元数据、次要说明、非激活状态 |
| `--rs-color-terrain` | `#49655D` | 开放地形曲线及极少量辅助图形 |
| `--rs-color-action` | `#A45B35` | 主要动作、推断链、关键分析转折 |
| `--rs-color-action-soft` | `#E7B580` | 深色导航上的激活文字和柔和强调 |
| `--rs-color-line` | `rgba(36, 59, 72, 0.22)` | 弱分隔线、面板边界 |
| `--rs-color-line-strong` | `rgba(36, 59, 72, 0.48)` | 页面区段、表头、重要结构边界 |
| `--rs-color-on-dark` | `#EDF0E9` | 深色导航上的普通文字 |
| `--rs-color-on-action` | `#FFFAF2` | 赭石实底按钮上的文字 |

颜色使用规则：

1. 页面以纸色、墨色和灰绿构成主要阅读环境。
2. 赭石只用于主要动作、分析路径、节点入口和少量激活状态。
3. 正文链接可以使用赭石并添加下划线，不能只用颜色表达可点击性。
4. 成功、警告和错误状态必须同时包含明确文字，不得只依赖色相。
5. 不新增高饱和辅助色来区分平台、阶段或模型。
6. 抖音与 B 站不使用平台品牌色占据卡片或表格背景。

### 3.3 字体

| 令牌 | 字体栈 | 用途 |
|---|---|---|
| `--rs-font-ui` | `"Avenir Next", "PingFang SC", "Gill Sans", sans-serif` | 导航、按钮、标签、表格和普通 UI |
| `--rs-font-reading` | `"Avenir Next", "PingFang SC", sans-serif` | Agent 分析、评论、阶段笔记和结论 |

字体规则：

1. 拉丁文字优先使用 `Avenir Next`。
2. 中文优先使用 `PingFang SC`。
3. `Gill Sans` 仅作为拉丁文字后备。
4. 正文不使用全大写。
5. 全大写只允许出现在极短的状态眉题或机器标识中。
6. 不使用极细字重承载正文。
7. 长篇分析以正常字距和舒展行高为主，不通过压缩字体提高密度。

### 3.4 字号与行高

| 令牌 | 字号 | 行高 | 建议字重 | 用途 |
|---|---:|---:|---:|---|
| `--rs-type-page-title` | `32px` | `1.16` | `550–600` | 页面和机会标题 |
| `--rs-type-section` | `18px` | `1.35` | `650–700` | 页面内主要区段 |
| `--rs-type-subsection` | `16px` | `1.4` | `650–700` | 面板和工作区标题 |
| `--rs-type-body` | `15px` | `1.65` | `400–500` | Agent 分析与长正文 |
| `--rs-type-ui` | `14px` | `1.45` | `500–650` | 按钮、表格和普通 UI |
| `--rs-type-meta` | `12px` | `1.5` | `450–600` | 时间、平台、模型与运行信息 |
| `--rs-type-eyebrow` | `12px` | `1.3` | `700` | 极短状态眉题 |

字号规则：

1. 正文默认使用 `15px`，允许高密度表格使用 `14px`。
2. 元数据不得小于 `12px`。
3. 代表评论与阶段笔记不得使用比元数据更小的字号。
4. 页面标题通常使用 `30–32px`，长标题允许换行，不通过压缩到小字号避免换行。
5. Agent 分析正文优先保持 `1.6–1.7` 行高。

### 3.5 间距

| 令牌 | 值 | 用途 |
|---|---:|---|
| `--rs-space-1` | `4px` | 标签内部微间距 |
| `--rs-space-2` | `8px` | 紧密关联元素 |
| `--rs-space-3` | `12px` | 控件内部与元数据组 |
| `--rs-space-4` | `16px` | 普通面板内边距 |
| `--rs-space-5` | `24px` | 区段内部间距 |
| `--rs-space-6` | `32px` | 栏间距和页面标题区 |
| `--rs-space-7` | `40px` | 桌面页面水平留白 |
| `--rs-space-8` | `48px` | 大区段间距 |
| `--rs-space-9` | `64px` | 页面级节奏 |

间距规则：

1. 使用 4px 基础网格。
2. 同一组件内优先使用 `8px`、`12px` 和 `16px`。
3. 页面大区段之间优先使用 `32px`、`40px` 和 `48px`。
4. 不通过增加无意义留白掩盖信息组织问题。
5. 表格和长列表保持可扫描性，不把每一行拉成展示型卡片高度。

### 3.6 边界、圆角与阴影

| 令牌 | 值 | 用途 |
|---|---:|---|
| `--rs-border-hairline` | `1px solid var(--rs-color-line)` | 普通面板和分隔线 |
| `--rs-border-strong` | `1px solid var(--rs-color-line-strong)` | 重要区段和表头 |
| `--rs-radius-none` | `0` | 表格、主要面板和页面区段 |
| `--rs-radius-small` | `2px` | 按钮和紧凑控件 |
| `--rs-radius-pill` | `999px` | 仅小型事实/推断标签 |

阴影规则：

1. 普通内容面板不使用阴影。
2. 浮层、确认对话框和真正覆盖其他内容的元素可以使用单层低透明阴影。
3. 不使用多层彩色阴影、内发光或持续悬浮效果。
4. 内容层级优先由背景色差、边界、留白和排版表达。

### 3.7 动效

| 令牌 | 值 | 用途 |
|---|---:|---|
| `--rs-duration-fast` | `120ms` | hover、focus、按下反馈 |
| `--rs-duration-standard` | `160ms` | 选择、展开和轻量状态切换 |
| `--rs-ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 普通 UI 反馈 |

动效规则：

1. 背景地形曲线保持静止。
2. 推断链不做沿路径流动、箭头跑动或节点逐个弹入。
3. hover、focus 和选择反馈控制在 `120–180ms`。
4. 不使用弹跳、过冲、视差和无限循环动画。
5. 遵守 `prefers-reduced-motion`，必要时直接取消过渡。

## 4. 页面框架

### 4.1 目标尺寸

1. 页面按 `1280–1440px` 宽的 Mac 桌面浏览器设计。
2. 主内容容器建议最大宽度为 `1440px`。
3. 桌面页面左右内边距建议使用 `40px`，较窄窗口可收缩到 `24px`。
4. 产品不设计独立移动端形态。
5. 对较窄桌面窗口进行防御性适配，但不把桌面导航改造成移动应用。

### 4.2 顶栏

1. 顶栏使用 `--rs-color-ink` 作为背景。
2. 顶栏底部使用赭石细线建立品牌识别。
3. 普通导航文字使用 `--rs-color-on-dark`。
4. 当前页面使用 `--rs-color-action-soft` 文字表示激活。
5. 激活项不使用发光、渐变、胶囊背景或大面积色块。
6. 导航项固定遵循 `docs/Pages.md`：首页、新发现、孵化、归档、运行、设置。
7. Tag 模块设计完成前，不显示 Tags 入口或空白占位。

### 4.3 页面标题区

页面标题区按以下顺序组织：

1. 面包屑或页面上下文；
2. 极短状态眉题；
3. 页面标题；
4. 必要元数据；
5. 右上角页面级操作；
6. 强分隔线。

页面级操作与标题保持同一视觉层级，不把主要动作藏入行内文本或卡片底部。

### 4.4 异常条

异常条只在真实异常时出现：

1. 使用清晰文字说明问题和影响范围；
2. 提供直接行动入口；
3. 不使用整页红色背景；
4. 不与背景地形曲线混合；
5. 不把正常状态常驻展示为健康卡片。

## 5. 开放地形背景

### 5.1 设计目的

开放地形背景只用于建立 Stamen Atlas 的空间气质。它不是数据可视化，不表示需求强度、平台来源、运行状态、推荐程度或机会优先级。

### 5.2 SVG 结构

背景使用一张定制 SVG：

- 默认包含 5 条开放贝塞尔曲线；
- 所有曲线均无填充；
- 曲线从 SVG 画布外进入，并从画布外离开；
- 不存在闭合路径；
- 不存在共同圆心；
- 曲线间距不相等；
- 曲率不重复；
- 局部允许靠近或分离；
- `stroke-linecap` 使用圆形端点；
- 使用 `vector-effect="non-scaling-stroke"` 保持缩放后的线重。

### 5.3 位置与透明度

1. 曲线只集中在页面右上角或页头右侧。
2. 页面中部、主要正文左侧和长列表背景保持干净。
3. 颜色使用 `--rs-color-terrain`。
4. 单条线透明度控制在 `5%–8.5%`。
5. 线宽可以在约 `0.85–1.05px` 范围内轻微变化。
6. 同一屏通常只出现一组背景曲线。
7. 背景曲线不得复制到每个卡片、面板或列表行中。

### 5.4 响应规则

1. 宽度不足时优先裁切曲线，而不是压缩到正文上方。
2. 曲线不得引起横向滚动。
3. 较窄窗口中允许降低透明度或完全隐藏。
4. 曲线不能改变页面内容高度。
5. 曲线使用 `pointer-events: none`，不接受交互和焦点。

## 6. 动态推断链

### 6.1 用途

动态推断链用于机会详情页，完整呈现 Agent 如何从原始内容与评论证据推导出软件机会。

链路节点数量由 Agent 分析结果决定，不固定为 5 个或 7 个。示例中的 7 个节点只用于验证视觉和连接规则。

### 6.2 节点内容

每个节点至少包含：

1. 顺序编号；
2. 节点标题；
3. “事实”或“AI 推断”文字标签；
4. 完整正文；
5. 必要时包含评论、依据、限制或过滤理由。

节点规则：

1. 事实与 AI 推断标签不能只靠色相区分。
2. Agent 分析不得使用多行省略号截断。
3. 节点高度由内容自然撑开。
4. 三条代表评论可以在事实节点内形成并列证据区。
5. 长评论允许换行，不固定卡片高度。
6. 节点之间保持稳定的纵向顺序。

### 6.3 5px 回正走廊

节点和纵向骨架只能在一个最大宽度为 `5px` 的窄走廊内局部变化：

1. 第一节点与最后节点位于同一纵轴。
2. 中间节点可以向左或向右轻微偏移。
3. 所有偏移的最大值与最小值之差不得超过 `5px`。
4. 偏移不允许逐节点累计。
5. 不允许形成左右交替的蛇形布局。
6. 纵向曲线允许平缓 S 形变化。
7. 曲线任意区段的阅读方向总体向下，不横走、不回头、不形成钩子。

节点数量变化时，偏移应按总节点数量重新归一化。任何数量下都必须满足：

- 起点和终点同轴；
- 横向总跨度不超过 `5px`；
- 锚点 Y 坐标严格递增；
- 路径无自交；
- 内容框之间不重叠。

### 6.4 统一 SVG 坐标系

纵向骨架、圆形锚点和水平入口箭头必须在同一个 SVG 中绘制。

禁止以下实现：

- 纵向曲线使用 SVG、圆点使用 CSS 伪元素；
- 圆点使用 SVG、入口箭头使用 CSS 伪元素；
- 使用独立 SVG 分别绘制路径和节点；
- 依靠背景色遮住跨坐标系的断点；
- 用亚像素偏移反复修补连接误差。

统一 SVG 的视口覆盖完整推断链高度。布局改变、节点高度变化或容器宽度变化后，所有锚点和路径必须基于同一组测量结果重新计算。

### 6.5 绘制顺序

SVG 内部固定按以下顺序绘制：

1. 纵向贝塞尔骨架；
2. 水平入口箭头；
3. 圆形锚点。

原因：

- 纵向曲线在最下层保持连续；
- 水平箭头从圆心开始绘制；
- 最后绘制的实底圆点覆盖圆内的路径和箭杆；
- 可见的纵向曲线精确接到圆点上下边缘；
- 可见的水平箭杆精确从圆点右边缘开始；
- 所有连接在任何缩放比例下保持无缝。

### 6.6 纵向骨架

| 令牌 | 值 | 用途 |
|---|---:|---|
| `--rs-chain-route-width` | `1.7px` | 纵向贝塞尔骨架 |
| `--rs-chain-corridor` | `5px` | 横向变化最大范围 |

纵向骨架规则：

1. 使用 `--rs-color-action`。
2. 不添加方向箭头。
3. 不使用虚线。
4. 不使用渐变描边。
5. 不沿路径播放流动动画。
6. 骨架只表示所有节点属于同一条推断链。

### 6.7 圆形锚点

| 令牌 | 值 | 用途 |
|---|---:|---|
| `--rs-chain-anchor-size` | `8px` | 圆点外径 |
| `--rs-chain-anchor-stroke` | `1.5px` | 圆点描边 |

圆形锚点规则：

1. 填充使用 `--rs-color-paper`。
2. 描边使用 `--rs-color-action`。
3. 圆心与对应内容框入口箭头共享同一 Y 坐标。
4. 圆点数量与实际节点数量一致。
5. 圆点不表示完成、强度、风险或模型置信度。

### 6.8 水平入口箭头

水平箭头表示“由链路进入这个内容节点”，不表示整条链路的阅读方向。

箭头规则：

1. 每个节点对应一支箭头，包括第一个节点。
2. 箭杆完全水平。
3. 箭杆上下边围绕圆心严格对称。
4. 箭头从圆心开始绘制，再由圆点覆盖左侧重叠部分。
5. 可见箭杆从圆点右边缘开始。
6. 箭头尖端抵达内容框左边界。
7. 箭杆建议视觉厚度为 `2px`。
8. 箭头头部建议总高度为 `8px`。
9. 箭头使用 `--rs-color-action`。
10. 箭头不旋转、不向下倾斜、不跟随纵向曲线切线。

### 6.9 动态布局边界

1. `0` 个节点时不绘制推断链，显示明确空状态或分析失败状态。
2. `1` 个节点时只绘制一个圆点和一支水平入口箭头，不绘制纵向骨架。
3. `2` 个及以上节点时绘制贯穿全部锚点的纵向骨架。
4. 节点高度变化后，圆心、入口箭头和纵向路径必须重新对齐。
5. SVG 不得使用固定高度假设 Agent 总是输出相同长度内容。
6. 推断链本身不得产生独立横向滚动条。

## 7. 容器与内容面板

### 7.1 内容面板

1. 使用 `--rs-color-surface` 作为主要表面。
2. 使用 `--rs-border-hairline` 作为普通边界。
3. 默认不使用阴影。
4. 默认使用直角。
5. 面板内边距通常使用 `16–24px`。
6. 面板高度由内容决定。
7. 不使用左侧彩色粗条代替真实结构。

### 7.2 事实与推断标签

1. 标签使用文字“事实”或“AI 推断”。
2. 标签允许使用小型胶囊圆角。
3. 事实标签使用墨色或强分隔线描边。
4. AI 推断标签使用赭石描边和赭石文字。
5. 标签不得替换节点标题。
6. 标签不得显示模型置信等级或需求强度。

### 7.3 代表评论

1. 评论区域在事实节点或机会卡片内部呈现。
2. 三条代表评论来自不同用户。
3. 使用细赭石竖线建立引用语义。
4. 评论可以并列，也可以在较窄窗口中纵向排列。
5. 评论文字不得截断到失去需求语义。
6. 不显示头像、视频画面或缩略图。

### 7.4 表格与列表

1. 孵化、归档和运行页面优先使用结构化表格。
2. 表格使用横向分隔线、对齐和留白，不把每一行放入独立浮动卡片。
3. 表头使用强分隔线或轻微纸面色差。
4. 当前行或可点击行使用短暂背景变化，不使用永久发光。
5. 状态以文字为主，不使用一排多色圆点。
6. 空状态不伪造示例数据填充。

## 8. 控件

### 8.1 主要按钮

1. 使用 `--rs-color-action` 实底。
2. 文字使用 `--rs-color-on-action`。
3. 默认使用 `--rs-radius-small`。
4. 按钮文案直接表达动作，例如“标记感兴趣”“开始可行性验证”“进入 CA”。
5. 一个操作区通常只保留一个主要按钮。

### 8.2 次要按钮

1. 使用透明或纸色背景。
2. 使用强分隔线描边。
3. 文字使用 `--rs-color-ink`。
4. 不通过降低到不可读的透明度弱化。

### 8.3 破坏性操作

1. 使用明确文案，例如“放弃”“拒绝并归档”。
2. 不只依赖红色表示危险。
3. 不可逆操作必须二次确认。
4. 确认界面说明对象、结果和不可恢复性。
5. 破坏性操作不与主要正向操作使用相同实底样式。

### 8.4 输入与编辑

1. 输入框使用纸色或抬升表面。
2. 默认边界使用强分隔线。
3. focus 使用赭石边界或外轮廓，不移除可见焦点。
4. 阶段笔记按独立条目编辑，不使用一个大文本框承载全部笔记。
5. 链接与照片作为笔记附件呈现，不与正文输入混成一个不可辨认区域。

### 8.5 阶段标签

1. 当前阶段必须明显。
2. 已完成、当前和锁定状态同时使用文字与结构变化。
3. 锁定状态不可只通过降低透明度表达。
4. 阶段标签不使用五种不同高饱和颜色。
5. 下一阶段按钮只有在完成条件满足后才启用，但仍需用户主动点击推进。

## 9. 页面应用原则

### 9.1 首页

1. 背景曲线只允许出现在页头或右上区域。
2. 左侧工作区与右侧 Token 指标栏保持清晰分区。
3. 最近新发现保持精简，不在首页复制完整推断链。
4. 首页的新发现卡片不重复展示完整三条评论。
5. Token 指标栏保持功能化，不加入地形装饰。
6. 正常状态不展示常驻健康卡片。

### 9.2 新发现列表

1. 机会卡片保持“机会优先 + 三条评论证据”。
2. 卡片使用纸面色差和细边界，不使用大阴影。
3. 整张卡片是唯一主交互。
4. 不展示视频、缩略图、头像和媒体播放器。
5. 不增加需求强度、置信度或排行榜标记。
6. Tag 模块完成设计前不显示 Tag 筛选。

### 9.3 机会详情

1. 这是 Stamen Atlas 隐喻最完整的页面。
2. 页面使用开放地形背景，但背景只能停留在右上角。
3. 决策依据使用动态推断链。
4. 推断链完整显示事实、评论、推断过程、软件机会和过滤理由。
5. 来源、样本、审计和媒体处理边界放入辅助信息区。
6. 新发现状态的“放弃”和“标记感兴趣”放在页面标题区右上角；感兴趣状态由用户明确执行“开始可行性验证”。
7. 页面不显示视频、缩略图或关键帧。

### 9.4 孵化工作区

1. 保留纸面、细线和赭石动作语法。
2. 阶段状态、完成条件和下一步必须比背景曲线更显眼。
3. 默认不在工作区重复铺设完整地形背景。
4. 阶段笔记以独立条目呈现。
5. 每条笔记支持必填文本、可选外链和最多一张照片。
6. 笔记排序、版本历史、结论和推进按钮使用结构化布局。
7. 不使用 AI 自动填写或自动推进的视觉暗示。

### 9.5 孵化列表与归档

1. 使用结构化表格。
2. 使用文字字段表达阶段、结果、原因和更新时间。
3. 行级操作保持克制。
4. 恢复、不可逆终态和确认动作使用明确文案。
5. 不使用地形背景装饰表格主体。

### 9.6 运行与运行详情

1. 运行列表使用表格呈现状态、平台、预算、Token 和时间。
2. 运行详情使用清晰的步骤与平台结果区段。
3. 失败、取消和重试必须显示具体阶段和影响。
4. Token 是功能数据，不使用大号宣传式统计卡。
5. 地形曲线可以完全省略。

### 9.7 设置

1. 使用左侧设置导航和右侧配置表单。
2. 各设置区段使用分隔线，不堆叠浮动卡片。
3. 模型、平台、调度、预算、保留策略和许可证保持同一控件语法。
4. 来源与许可证页面以清晰文字标明 BettaFish 来源。
5. Tag 模块未完成设计前不出现相关设置。

## 10. 状态与可访问性

### 10.1 加载

1. 使用与最终内容结构一致的骨架。
2. 推断链加载时保留节点与辅助信息区的空间关系。
3. 不使用全页旋转指示器。
4. 背景曲线不参与加载动画。

### 10.2 空状态

1. 说明当前没有什么。
2. 只在存在真实下一步时显示操作。
3. 搜索无结果与数据本身为空使用不同文案。
4. 不伪造机会、评论或 Token 数据填充页面。

### 10.3 错误

1. 可恢复错误在相关内容附近显示。
2. 显示原因和重试入口。
3. 不可恢复错误说明受影响的数据范围。
4. 不用装饰性插画掩盖错误信息。

### 10.4 键盘与焦点

1. 所有可交互元素必须可通过键盘访问。
2. focus 状态必须可见。
3. 整行或整卡可点击时，语义上仍需提供可聚焦元素。
4. 颜色不能成为状态的唯一表达方式。
5. 链接使用下划线、明确文案或其他非颜色提示。

### 10.5 对比度与缩放

1. 正文、按钮和链接必须满足常规文字可读性要求。
2. 低透明度地形曲线不承载信息，因此可以保持弱对比。
3. 浏览器放大后，SVG 路径、锚点和入口箭头必须保持无缝连接。
4. SVG 使用同一坐标系和非缩放描边，避免亚像素断点。
5. 页面放大后不得通过隐藏 Agent 内容维持布局。

## 11. 前端实现契约

### 11.1 稳定令牌

后续实现至少暴露以下令牌组：

- `--rs-color-*`
- `--rs-font-*`
- `--rs-type-*`
- `--rs-space-*`
- `--rs-border-*`
- `--rs-radius-*`
- `--rs-duration-*`
- `--rs-ease-*`
- `--rs-chain-route-width`
- `--rs-chain-corridor`
- `--rs-chain-anchor-size`
- `--rs-chain-anchor-stroke`

页面和组件不得直接复制未命名的相近颜色替代令牌。

### 11.2 推断链输入

推断链组件至少需要以下语义输入：

| 输入 | 说明 |
|---|---|
| 节点顺序 | Agent 输出的稳定顺序 |
| 节点类型 | 事实或 AI 推断 |
| 节点标题 | 当前分析步骤名称 |
| 节点正文 | 完整分析内容 |
| 节点附加证据 | 评论、依据或限制，可为空 |
| 容器尺寸 | 用于重新计算 SVG 锚点和路径 |

本设计系统不规定具体 JSON 字段名称，但前端不得根据正文长度猜测节点类型或顺序。

### 11.3 推断链几何不变量

任何实现都必须满足：

1. 实际节点数量等于圆点和水平箭头数量。
2. 两个及以上节点时只有一条纵向骨架。
3. 第一和最后锚点同轴。
4. 所有锚点的横向跨度不超过 `5px`。
5. 所有锚点 Y 坐标严格递增。
6. 水平箭杆与对应圆心共享同一 Y 坐标。
7. 箭头尖端抵达对应内容框左边界。
8. 纵向骨架、水平箭头和圆点位于同一个 SVG。
9. SVG 绘制顺序固定为骨架、箭头、圆点。
10. 路径、圆点和箭头之间没有可见断点、凸出或错位。

### 11.4 非业务接口

本设计系统不新增：

- 业务 API；
- 数据库字段；
- Agent 输出字段；
- 路由；
- 后台任务；
- MCP 工具；
- Tag 规则。

如果未来业务接口变化，只要页面语义不变，设计令牌与连接图形契约继续有效。

## 12. 设计验收清单

### 12.1 全局

- [ ] 页面使用纸色、墨色、灰绿与赭石构成主要色彩。
- [ ] UI 文案简短，Agent 分析完整。
- [ ] 未使用蓝紫 AI 渐变、发光光晕和大圆角卡片。
- [ ] 主要动作与次要动作层级明确。
- [ ] 状态不只依赖颜色表达。
- [ ] 页面没有视频、缩略图或播放器。
- [ ] 页面没有未完成的 Tag 控件。

### 12.2 背景曲线

- [ ] 使用开放 SVG 贝塞尔曲线，不使用径向渐变。
- [ ] 曲线无闭环、无共同圆心、无等距复制。
- [ ] 曲线只出现在页头或右上区域。
- [ ] 曲线透明度约为 `5%–8.5%`。
- [ ] 曲线不承载状态或数据。
- [ ] 曲线不造成横向滚动。

### 12.3 动态推断链

- [ ] 节点数量由 Agent 输出决定。
- [ ] 事实与 AI 推断具有文字标签。
- [ ] 节点内容没有被截断。
- [ ] 起点和终点同轴。
- [ ] 横向总跨度不超过 `5px`。
- [ ] 没有左右交接式蛇形布局。
- [ ] 纵向骨架没有方向箭头。
- [ ] 每个节点具有圆点和水平向右箭头。
- [ ] 骨架、箭头和圆点位于同一个 SVG。
- [ ] 水平箭杆严格对齐圆心。
- [ ] 箭头始端从圆点右边缘显现。
- [ ] 箭头尖端抵达内容框左边界。
- [ ] 所有连接无断点、无凸出、无亚像素错位。

### 12.4 页面应用

- [ ] 首页保持工作区与 Token 指标栏结构。
- [ ] 新发现列表保留三条代表评论。
- [ ] 机会详情完整使用动态推断链。
- [ ] 孵化工作区优先展示阶段、笔记和完成条件。
- [ ] 孵化、归档和运行列表使用结构化表格。
- [ ] 设置页面不出现 Tag 模块。
- [ ] 地形背景没有被复制到每个面板。

## 13. 最终决定摘要

1. 最终视觉方向为 Stamen Atlas。
2. 背景使用弱化的开放地形 SVG，不使用规则同心圆或径向渐变。
3. Agent 推断节点数量动态变化，不固定为 5 个或 7 个。
4. 推断链在最大 `5px` 窄走廊内局部变化，起点与终点同轴。
5. 纵向曲线不使用方向箭头。
6. 每个圆形锚点使用水平向右箭头指向对应内容框。
7. 纵向曲线、圆点和入口箭头统一在同一个 SVG 坐标系中绘制。
8. UI 保持简洁，Agent 分析完整展示。
9. Tag 模块不属于当前设计系统的可实现页面范围。
