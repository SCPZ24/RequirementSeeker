## 2. 主要发现

### R1 / P1：全部 P0 前置会造成协作相互等待

**依据：** [开放问题清单](../OPEN_QUESTIONS.md) 原“使用规则”第 3 项和“实施计划生成门槛”，要求所有 P0 关闭才制定精确计划；P0 中包含前端技术、整个产品进程、终态纠错等非 Agent 前置项。

**影响：** 发起者等 Agent 交付，Agent 又等发起者完成全栈设计，双方难以进入实现。

**处理：** 本次根据用户新的协作说明改为阶段门槛。领域契约、样本和纯规则先行；数据库、页面和系统部署决定移到对应接入阶段。保留未决问题，不把未知答案勾选为已解决。

### R2 / P1：输入契约不足以支撑跨日三人共识

**依据：** PRD FR-4、FR-9、AC-9 要求十天内新增评论可加入旧簇；Agent 设计的输入契约仅列出视频、评论、可选媒体和执行上下文，未规定历史簇状态、有效期与完整快照/增量输入语义。

**影响：** 第一天两人、第二天一人的输入若各自独立分析，永远无法通过；若简单累加人数，又可能重复计数或使用已过期评论。

**建议：** 第一版采用单视频有效评论快照输入，携带采集时间与逐条到期信息，由调用方组装保留期内数据；Agent 按固定时钟重新计算作者集合。离线 runner 模拟历史状态。若以后接受增量事件，需要新增显式状态端口和幂等语义，不能悄悄变更输入含义。

**验收：** 同视频“2 + 1”在有效期内通过；重复作者不通过；过期旧评论不参与；不同视频永不拼接计数。

### R3 / P1：确定性要求尚未覆盖模型重跑的波动

**依据：** PRD §9.2 第 4 项和 Agent 设计“已确认的设计决策”第 5 项要求相同输入得到一致准入结果；同时模型参与信号识别及语义聚类。

**影响：** 只把最后的作者计数写成确定性代码，仍不能保证模型每次把相同评论放进同一个簇。规则测试通过不等于全链路重跑一致。

**建议：** 固化输入快照、模型配置/能力、规则、提示词和 Schema 版本，缓存经过校验的语义结果用于同一分析键重放；缓存保留期遵守原始数据期限。首次模型推理单独做金标评测，不承诺仅凭低温度就可复现。版本变化视为新分析，不能改写历史已提交证据。

**待定边界：** 缓存过期后的重分析是否属于同一分析，以及供应商模型版本不可固定时如何标记，需要在实现前的模块 ADR 中写明。

### R4 / P1：正式机会、合并和重试缺少明确提交边界

**依据：** PRD FR-13、§9.2、§10.5 要求证据合并、幂等和崩溃恢复；Pages §12.2–12.3 要求安全取消及新建关联重试运行；Agent 输出只有概念名称。

**影响：** 如果 Agent 直接新增数据库机会而调度器再次提交，可能出现重复；如果失败或取消也用空数组表示，后端会误报“成功但零机会”。

**建议：** Agent 输出分析结果和带稳定幂等键的提交意图；后端拥有正式 ID、唯一约束、证据事务和运行持久化。明确定义新候选、合并建议、拒绝、上下文不足、错误、预算结束、取消等结果，以及失败步骤、可重试性、原运行关系。离线存储替身验证协议，真实事务在后续联调验收。

### R5 / P1：可审计输出不等于永久保存全部模型正文

**依据：** PRD FR-20 明确十天原始数据期限和正式机会证据例外；Pages §7.3 要求完整展示推断链。

**影响：** 把整段模型输出直接当推断链或永久审计保存，会把未选中的普通评论、OCR 或字幕一起永久留存；只留引用又可能在清理后出现失效的正式证据。

**建议：** 分开保存短期原始材料、正式机会证据包、长期审计元数据。推断链是面向用户的结构化依据说明：事实节点引用已校验证据，推断节点说明结论与限制，不要求保存模型内部思考过程。持久化层必须先原子提交正式证据，再允许短期数据清理。

**验收：** 到期后普通正文和缓存清理；正式证据仍可读；审计元数据仍可追溯；模型自由编造的评论 ID 或引文不能成为事实节点。

### R6 / P2：模型、预算与评测仍停留在问题列表

**依据：** 开放问题 P0-008、P0-010、P1-001–P1-010；PRD FR-19 和成本要求。

**影响：** 容易先实现向量检索或复杂 Agent 框架，再发现与单模型约束冲突；单次成功演示也不能证明语义识别稳定。

**建议：** 首期采用同一配置模型、可替换调用接口和小规模历史候选召回，不引入第二嵌入模型或 ACP/MCP。先用假模型验证流程，再用标注样本评价真实模型。预算、修复和重试必须有限，usage 缺失不能记成真实零用量。

**验收：** 确定性不变量全部通过；真实模型报告区分规则通过率、语义精确率、召回率、误合并、用量与失败率。阈值在看评测结果之前定义，小样本表现不得宣称为生产质量。

### R7 / P2：开发环境与目标运行环境不同，仓库缺少交付入口

**依据：** PRD §4.2 指定个人 Mac；当前工作目录位于 Windows；README 只有一句简介，仓库无依赖、测试和 CI 配置。

**影响：** 在 Windows 上跑通脚本仍不足以证明用户能在 Mac 安装使用；发起者也无法凭设计文档接入代码。

**建议：** Agent 保持可移植库形式；建立安装说明、离线示例和测试入口，提交前完成 Windows 与 macOS 的核心验证。依赖锁定、敏感文件忽略和调用配置样例随模块一起交付。具体工具版本在建立工程底座时验证并锁定。

## 3. 已确认约束与无需扩大的工作

- 三人共识只能在同一个视频中成立；跨视频、跨平台合并仅发生在已准入机会之间。
- 无稳定作者 ID、视频作者自己的评论、重复作者不能被用来凑足门槛。
- 先验证评论信号及共识，再在文本不足时请求多模态。
- 不支持视觉或上下文仍不足时，不生成猜测性的机会。
- 软件可解、非重运营、自然获客路径必须明确；不进行强度分级或固定排名。
- 人工阶段笔记、状态与结论不由 Agent 自动填写或覆盖。
- 视觉按现有 Stamen Atlas 实现，Tag 不在当前交付范围内。
