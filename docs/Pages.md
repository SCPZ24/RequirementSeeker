# RequirementSeeker MVP 页面设计

- 文档状态：页面、交互与设计系统已确认，Tag 模块待重新设计
- 版本：MVP 页面设计草案 v1
- 日期：2026-07-27
- 最近一致性审查：2026-09-04
- 目标设备：用户个人 Mac 上的桌面浏览器
- 启动方式：`rs dashboard`
- 产品访问范围：仅 `localhost`
- 关联需求文档：`docs/PRD.md`
- 关联设计系统：`docs/design.md`（Stamen Atlas，最终定稿）

## 1. 文档用途

本文档记录 RequirementSeeker MVP 已确认的页面清单、页面职责、功能、布局、状态与交互规则。

本文档不包含前端技术选型、组件代码、接口设计和视觉像素稿。Tag 模块的需求、数据规则和管理页面尚未完成设计，不属于本文档的可实现范围。

## 2. 页面设计边界

### 2.1 用户与使用场景

1. 产品只有一位用户，即 RequirementSeeker 的拥有者。
2. 用户通过 `rs dashboard` 启动本地 Web 应用。
3. 页面只面向 Mac 桌面浏览器，不设计移动端产品形态。
4. 首页不是经营数据大屏，而是用户回来后快速判断“现在该处理什么”的工作台。
5. AI 只负责发现、整理和解释潜在软件机会。
6. 可行性验证、CA、需求分析、获客方案和最终决策全部由用户人工完成。

### 2.2 不在页面中实现的能力

1. 不提供注册、登录、团队、权限和租户页面。
2. 不提供主动推送、通知中心或日报页面。
3. 不提供视频播放器、视频缩略图或视频媒体库。
4. 不提供 Top 3、排行榜或需求强度等级。
5. 不提供 AI 自动孵化、AI 自动填写检查项或 AI 自动推进阶段。
6. 不提供产品开发、版本、发布和运营管理页面。
7. 当前不提供 Tag 管理页面。Tag 模块需单独完成下一轮需求脑暴。

## 3. 全局信息架构

### 3.1 顶栏一级导航

MVP 当前使用网站式顶栏。导航项按以下顺序固定：

1. 首页
2. 新发现
3. 孵化
4. 归档
5. 运行
6. 设置

Tag 模块未完成设计前，顶栏不显示 Tags 入口，也不预留空白占位。

### 3.2 页面清单

| 页面 | 建议路由 | 主要职责 |
|---|---|---|
| 首页 | `/` | 展示当前最需要关注的机会和近期 Token 用量 |
| 新发现 | `/discoveries` | 浏览所有等待用户判断的新机会 |
| 机会详情 | `/opportunities/:id` | 查看完整发现依据，并根据状态完成决策或孵化 |
| 孵化 | `/incubation` | 以结构化列表查看所有孵化中机会 |
| 归档 | `/archive` | 查看决定开发、暂缓和放弃的机会 |
| 运行 | `/runs` | 比较历次探测任务的状态和消耗 |
| 运行详情 | `/runs/:id` | 查看单次任务的过程、平台结果、预算和错误 |
| 设置 | `/settings/:section` | 管理本机模型、平台、调度、预算、保留策略和许可证 |

“新发现详情”和“孵化详情”不是两套页面。它们共用机会详情路由和数据结构，由机会状态决定默认视图与可用操作。

### 3.3 全局页面框架

1. 顶栏固定承载产品名称和一级导航。
2. 当前页面必须具有明确的激活状态。
3. 页面主体使用桌面优先的内容容器，基准宽度按 1280-1440 像素设计。
4. 页面标题、搜索、筛选和页面级操作放在内容区顶部。
5. 正常状态不常驻展示模型、平台和调度健康卡片。
6. 漏跑、平台登录失效、模型不可用等异常发生时，在顶栏下方显示横向异常条。
7. 异常条必须包含问题、影响范围和直接行动入口。

## 4. 跨页面设计原则

### 4.1 专业工具语气

1. UI 文案必须简短、直接、功能化。
2. 不使用面向初学者的教学式解释、鼓励语和重复提示。
3. 不使用营销文案、拟人化问候和为了填充空间而添加的副标题。
4. 页面只解释当前操作真正需要解释的规则。
5. Agent 分析正文、证据、推断依据和过滤理由必须完整显示，不能为了视觉简洁而截断实质内容。

### 4.2 事实与推断分离

1. 原始场景和评论证据标记为事实。
2. 需求抽象、软件机会和准入理由标记为 AI 推断。
3. 每个 AI 推断节点应展示其依据。
4. UI 不替 Agent 结论添加额外强度、信心或推荐等级。

### 4.3 媒体边界

1. Web 页面不展示视频、缩略图、关键帧或播放器。
2. 页面只保存并展示平台名称、原视频标题、必要文字上下文和原页面外链。
3. 后台仍可按照 PRD 在三人候选成立且文字上下文不足时按需处理视频。
4. 后台多模态处理中间产物不自动成为 Web 展示资产。

### 4.4 容器与信息密度

1. 卡片只在表达真实层级或独立可点击对象时使用。
2. 表格和长列表优先使用网格、留白和单向分隔线，不为每行增加多余卡片。
3. 不使用三等分通用 SaaS 卡片作为默认页面结构。
4. 不使用无意义图标、装饰性统计、渐变光晕和多色状态圆点。
5. 数字、状态和操作必须比装饰更显眼。

### 4.5 通用状态

1. 加载状态使用与最终内容结构匹配的骨架，不使用全页旋转指示器。
2. 空状态只说明“当前没有什么”以及必要的下一步，不伪造示例机会填充页面。
3. 可恢复错误在当前内容附近显示原因和重试入口。
4. 破坏性或不可恢复操作必须二次确认。
5. 搜索无结果与页面本身没有数据是两种不同空状态。

## 5. 首页

### 5.1 页面目标

用户打开应用后，应在 30 秒内回答：

1. 最近出现了哪些等待判断的新机会？
2. 最近正在孵化的机会下一步做什么？
3. 最近一次探测和近七天消耗了多少 Token？

### 5.2 布局

首页采用“工作区 + 指标栏”布局：

1. 左侧为主要工作区。
2. 右侧为固定宽度的 Token 指标栏。
3. 左侧先显示新发现，再显示继续孵化。
4. 右侧只显示 Token，不混入系统健康、平台状态和数据清理统计。

### 5.3 最近新发现

1. 展示最近发现且仍等待用户判断的 3 个机会。
2. 默认按首次发现时间倒序。
3. 每个机会以精简卡片呈现。
4. 首页卡片只进入机会详情，不在首页直接执行感兴趣或放弃。
5. 卡片至少显示：
   - 机会标题；
   - 一句软件机会摘要；
   - 平台；
   - 独立用户人数；
   - 发现时间。
6. 首页不需要重复展示完整三条评论，完整证据由新发现列表和详情页承载。
7. 区块提供“查看全部”，进入新发现页。

### 5.4 继续孵化

1. 展示最近更新的 3 个孵化中机会。
2. 排序只依据最近更新时间，不使用 AI 推荐或优先级评分。
3. 每行显示：
   - 机会标题；
   - 当前阶段；
   - 当前阶段完成数与总检查项数；
   - 下一项行动；
   - 最近更新时间。
4. “下一项行动”按确定性规则生成：
   - 当前状态为“感兴趣”时，显示“开始可行性验证”；
   - 当前阶段尚有未完成检查项时，显示第一个未完成检查项；
   - 检查项已完成但阶段结论为空时，显示“填写阶段结论”；
   - 当前阶段全部完成时，显示“进入下一阶段”。
5. 点击整行进入机会详情的当前阶段工作区。

### 5.5 Token 指标栏

1. 只展示纯 Token 统计，不估算金额。
2. 固定展示两个时间口径：
   - 最近一次探测；
   - 近 7 天合计。
3. 以模型用量表格呈现，字段至少包括：
   - 模型名称；
   - 输入 Token；
   - 输出 Token；
   - 总 Token。
4. 当前 MVP 只配置一个模型，但表格结构不把模型名写死。
5. 指标栏提供进入相关运行详情或运行列表的入口。

### 5.6 首页异常条

异常条只在以下情况出现：

- 今日计划任务尚未执行；
- 抖音或 B 站登录失效；
- 模型连接或能力检测失败；
- 调度未安装或失效；
- 最近维护清理失败。

异常条不自动补跑任务。漏跑时只提供“立即探测”入口。

## 6. 新发现页

### 6.1 页面目标

以机会为单位快速扫描所有等待决策的发现，并进入详情完成判断。

### 6.2 列表布局

1. 机会以卡片网格呈现。
2. 默认按发现时间倒序。
3. 支持搜索。
4. 支持按平台筛选。
5. 支持按发现时间排序。
6. Tag 模块完成设计前，不提供 Tag 筛选。
7. 整张卡片是唯一的主交互，点击进入详情。
8. 卡片上不放感兴趣和放弃按钮。

### 6.3 卡片内容

采用“机会优先 + 三条评论证据”的组合：

1. 机会标题；
2. 软件机会摘要；
3. 用户期望获得的核心结果；
4. 三条来自不同用户的代表性评论；
5. 独立用户人数；
6. 平台；
7. 发现时间。

卡片不显示：

- 视频；
- 视频缩略图；
- 作者头像；
- 需求强度；
- AI 分数；
- 点赞数；
- 多余的操作按钮。

卡片可以对长分析进行摘要，但三条代表性评论不得合并成一条。

## 7. 机会详情页

### 7.1 共用详情模型

所有机会共用同一个详情页：

- 新发现状态默认显示“发现依据”；
- 感兴趣状态默认显示“发现依据”，并提供“开始可行性验证”操作；
- 孵化中状态默认显示“孵化”；
- 归档状态默认显示归档结果，同时允许只读查看发现依据和历史孵化内容。

### 7.2 页头

页头固定显示：

1. 返回来源列表；
2. 机会标题；
3. 当前状态；
4. 发现时间与平台；
5. 当前状态允许的主操作。

新发现状态的操作位于页头右侧：

- 放弃；
- 标记感兴趣。

感兴趣状态的主要操作为“开始可行性验证”。该操作必须由用户明确触发，不得在标记感兴趣时自动执行。

上述新发现状态的两个按钮均只在机会详情页出现，不出现在首页或新发现列表。

### 7.3 动态推断链

发现依据采用由箭头连接的有序 Panel 链。

1. Panel 数量不固定。
2. AI 根据具体机会生成满足结构化 Schema 的若干节点。
3. UI 根据顺序渲染所有节点，不把推断链写死为五步。
4. 每个节点至少包含：
   - 节点标题；
   - 节点类型：事实或 AI 推断；
   - 完整正文；
   - 可选的推断依据；
   - 可选的证据引用。
5. 至少必须覆盖：
   - 原始场景；
   - 三位不同用户的共同需求；
   - 需求抽象；
   - 软件机会；
   - 不依赖重运营的理由；
   - 自然获客路径。
6. 一个节点可以同时承载多个相关理由，但不得把事实和 AI 推断混在同一段中且不标记。
7. UI 不截断 Agent 分析正文。

### 7.4 评论证据

1. 至少展示三条来自不同用户的代表性评论。
2. 每条评论展示匿名作者标识。
3. 评论正文完整显示。
4. 评论之间不得因视觉布局被合并。
5. 可以展示评论时间和一级/二级关系，但不显示需求强度。

### 7.5 辅助信息

辅助区域至少包含：

- 原始平台；
- 原视频标题；
- 原页面外链；
- 分析模型；
- 提示词或分析版本；
- 分析时间；
- 证据保留状态；
- 状态与决策历史。

Tag 来源路径暂不属于已完成的页面设计，在 Tag 模块重新设计前不显示。

### 7.6 新发现决策

1. “标记感兴趣”将机会移出新发现并进入孵化列表，当前状态保持为“感兴趣”。
2. 用户在感兴趣状态下明确点击“开始可行性验证”后，机会才进入可行性验证阶段。
3. “放弃”要求填写归档原因。
4. 放弃是不可恢复终局。
5. 放弃前必须二次确认。
6. 可选的初步判断文本随决策进入机会历史。

## 8. 孵化页

### 8.1 页面目标

以结构化列表回答每个孵化中机会目前处于什么阶段、完成多少、下一步做什么。

### 8.2 列表布局

孵化页采用结构化表格。默认按最近更新时间倒序。

字段固定为：

1. 机会；
2. 当前阶段；
3. 当前阶段进度；
4. 下一项行动；
5. 最近更新时间。

处于“感兴趣”且尚未开始可行性验证的机会，其当前阶段显示为“感兴趣”，下一项行动显示为“开始可行性验证”。

页面支持：

- 搜索；
- 按当前阶段筛选；
- 按最近更新时间排序；
- 点击整行进入当前阶段工作区。

列表不提供内联编辑、拖拽阶段或快速归档。

## 9. 孵化工作区

### 9.1 默认视图

1. 机会标记为感兴趣后进入孵化；在开始可行性验证前，详情页默认显示“发现依据”和“开始可行性验证”操作。
2. 进入可行性验证后，详情页默认显示当前阶段工作区。
3. 页面提供“发现依据”和“孵化”两个同级视图。
4. “发现依据”完整保留动态推断链，不能因进入孵化而丢失。

### 9.2 阶段布局

孵化工作区采用“阶段标签 + 文档编辑”布局。

阶段标签按以下顺序展示：

1. 可行性验证；
2. CA；
3. 需求分析；
4. 获客方案；
5. 决策就绪。

规则：

1. 阶段顺序解锁。
2. 未来阶段可见但只读。
3. 当前阶段可编辑。
4. 已完成阶段可返回查看和修改。
5. 系统不得因为检查项完成而自动推进阶段。
6. 检查项与阶段结论满足后，只启用“进入下一阶段”按钮。
7. 必须由用户明确点击推进。

### 9.3 当前阶段工作内容

每个阶段包含：

- 固定检查清单；
- 阶段笔记条目；
- 阶段结论；
- 当前完成状态；
- 进入下一阶段的操作。

阶段结论保持为一个结构化长文本字段。阶段笔记不使用单个大文本框。

### 9.4 阶段笔记

阶段笔记是一组独立条目。

每条笔记包含：

| 字段 | 规则 |
|---|---|
| 文本 | 必填 |
| 外链 | 可选，最多 1 个 |
| 照片 | 可选，最多 1 张 |
| 创建时间 | 系统生成 |
| 更新时间 | 系统生成 |
| 排序位置 | 用户手动调整 |
| 版本 | 每次编辑生成新版本 |

交互规则：

1. 用户可以添加、编辑和删除笔记。
2. 笔记支持拖拽手动排序。
3. 删除使用软删除，并保留在版本历史中。
4. 每条笔记可以展开查看完整版本历史。
5. 照片通过本地文件选择或粘贴添加。
6. 照片在笔记中显示缩略图，点击查看本地原图。
7. 替换照片也生成新版本。
8. 笔记文本为空时不得保存。
9. 外链和照片均为空时仍可保存纯文本笔记。
10. 阶段笔记、版本和照片属于人工孵化资料，永久保留，不受十天原始社媒数据清理影响。

## 10. 归档页

### 10.1 归档状态

归档页包含：

- 决定开发；
- 暂缓；
- 放弃。

### 10.2 列表布局

归档页复用孵化页的结构化表格模式，字段改为：

1. 机会；
2. 结果；
3. 归档前阶段；
4. 归档原因；
5. 归档时间。

默认按归档时间倒序，支持搜索和按结果筛选。

### 10.3 归档规则

1. 决定开发、暂缓和放弃都必须填写归档原因。
2. “决定开发”的归档原因与决策阶段结论分别保存。
3. 只有“暂缓”可恢复。
4. 暂缓恢复到归档前阶段。
5. 放弃和决定开发均为不可恢复终局。
6. 放弃和决定开发前必须二次确认。
7. 所有归档和恢复操作写入状态历史。

## 11. 运行页

### 11.1 页面目标

比较历次探测任务，明确区分：

- 成功并有发现；
- 成功但零结果；
- 部分平台失败；
- 完全失败；
- 正在运行；
- 已取消；
- 登录失效。

### 11.2 运行列表

运行页采用结构化表格，默认按开始时间倒序。

字段至少包括：

1. 开始时间；
2. 状态；
3. 运行时长；
4. 成功平台数与总平台数；
5. 视频数；
6. 评论数；
7. Token；
8. 新机会数。

页面支持：

- 按状态筛选；
- 按日期筛选；
- 进入运行详情；
- 立即探测。

### 11.3 立即探测

1. 点击“立即探测”先打开确认对话框。
2. 确认框展示本次平台和全局预算上限。
3. 用户确认后创建新运行。
4. 创建后立即进入实时运行详情。
5. 如果已有运行正在执行，不创建第二个运行，而是进入现有运行详情。

## 12. 运行详情页

### 12.1 页面内容

运行详情至少展示：

- 状态；
- 开始和结束时间；
- 当前步骤；
- 分步骤耗时；
- 抖音分项结果；
- B 站分项结果；
- 视频和评论预算使用；
- 模型名称、输入 Token、输出 Token 和总 Token；
- 新机会；
- 错误；
- 取消位置；
- 原运行与重试运行关系。

运行中页面采用实时更新，不要求用户手动刷新。

### 12.2 安全取消

1. 正在运行的任务允许取消。
2. 取消只停止尚未开始的新步骤。
3. 已提交的数据保留。
4. 运行状态标记为已取消。
5. 页面记录取消发生在哪个平台和处理步骤。
6. 取消操作需要确认。

### 12.3 失败重试

1. 重试创建一条新的关联运行。
2. 原失败运行保持不变。
3. 新运行只执行失败的平台或分析阶段。
4. 已成功部分依靠幂等记录复用。
5. 运行详情必须可以在原运行和重试运行之间跳转。

## 13. 设置页

### 13.1 内部导航

设置页采用左侧栏目导航，包含：

1. 模型；
2. 平台；
3. 调度；
4. 采集预算；
5. 数据保留；
6. 来源与许可。

每个栏目具有独立路由和独立保存范围。Tag 设置当前不显示。

### 13.2 模型

展示和管理：

- API Base URL；
- API Key 的掩码状态；
- 模型名称；
- 文本能力检测；
- 图像能力检测；
- 测试连接；
- 保存。

API Key 不回显明文。

### 13.3 平台

分别展示抖音和 B 站：

- 登录状态；
- 最近检查时间；
- 重新登录入口；
- 清除本地登录态；
- 最近平台错误。

### 13.4 调度

展示和管理：

- 每日运行时间；
- 当前系统时区；
- 调度安装状态；
- 下次计划时间；
- 安装或更新；
- 移除调度。

页面必须明确说明错过计划时间后不会自动补跑。

### 13.5 采集预算

当前仅管理与 Tag 无关的全局预算：

- 单次最大视频数；
- 单次最大评论数；
- 每个视频最大评论数；
- 平台启用状态。

Tag 级预算待 Tag 模块完成设计后补充。

### 13.6 数据保留

展示：

- 普通原始数据保留 10 天；
- 即将清理的数据量；
- 下次清理时间；
- 最近清理结果；
- 正式机会证据永久保留；
- 人工孵化笔记和照片永久保留。

MVP 不提供任意修改保留天数的功能，十天是固定产品规则。

### 13.7 来源与许可

展示并链接：

- BettaFish；
- MindSpider；
- MediaCrawler；
- 本地保留的许可证正文。

页面不暗示上游作者为 RequirementSeeker 提供担保。

## 14. 最终设计系统

最终视觉方向已经定稿为 **Stamen Atlas**。完整的视觉语言、设计令牌、动态推断链几何规则、组件约束和验收清单以 `docs/design.md` 为准。

此前参与比较的 Rams Control 仅属于历史候选，不再作为实现选项。前端实现不得重新在两个方向之间选择或混用其视觉规则。

## 15. 待重新设计的 Tag 模块

Tag 模块只保留产品方向，不保留当前页面方案。

下列内容全部待重新脑暴：

- 起始 Tag 的创建与编辑；
- 扩散 Tag 的产生与批准机制；
- 试探、活跃、休眠和停用状态；
- 权重如何展示和调整；
- 每日预算如何分配；
- 父子关系和扩散路径；
- 图谱是否必要；
- 反馈如何作用于探索方向；
- Tag 与热门池检索的精确接口；
- Tag 管理页面及其导航位置。

Tag 模块完成设计前：

1. 不实现 Tags 页面；
2. 不在顶栏显示 Tags；
3. 不把现有 PRD 中 Tag 条款当作可验收需求；
4. 不根据旧版 Tag 状态、权重和试探规则建立不可逆的数据结构；
5. 不把 Tag 相关内容纳入当前页面实现计划。

## 16. 已确认决策摘要

| 主题 | 决策 |
|---|---|
| 全局导航 | 网站式顶栏 |
| 当前顶栏 | 首页、新发现、孵化、归档、运行、设置 |
| 首页布局 | 左侧工作区 + 右侧 Token 指标栏 |
| 首页新发现 | 最近 3 个，只进入详情 |
| 首页孵化 | 最近更新 3 个，显示下一项行动 |
| 首页 Token | 最近任务 + 近 7 天，按模型展示输入/输出/总量 |
| 首页健康状态 | 仅异常时显示横幅 |
| 新发现列表 | 机会优先卡片 + 三条评论 |
| Web 视频 | 不展示视频、缩略图或播放器 |
| 后台视频理解 | 文本不足时仍允许按需多模态 |
| 机会详情 | 共用详情页 |
| 发现依据 | 数量可变的动态推断链 |
| 详情决策 | 新发现状态为放弃 / 标记感兴趣；感兴趣状态由用户开始可行性验证 |
| UI 文案 | 极简、专业，不使用教学式废话 |
| Agent 内容 | 完整展示，不为简洁牺牲实质 |
| 孵化列表 | 结构化表格 |
| 孵化工作区 | 阶段标签 + 文档编辑 |
| 阶段开放 | 顺序解锁，已完成可回看修改 |
| 阶段推进 | 用户明确点击，不自动推进 |
| 阶段笔记 | 独立条目，文本必填，外链可选，最多一张照片 |
| 笔记顺序 | 手动拖拽 |
| 笔记编辑 | 保留版本历史，删除为软删除 |
| 归档列表 | 复用结构化表格 |
| 归档原因 | 决定开发、暂缓、放弃均必填 |
| 归档恢复 | 仅暂缓可恢复 |
| 运行列表 | 结构化表格 + 独立详情 |
| 手动探测 | 确认平台和预算后进入实时详情 |
| 运行取消 | 安全取消，保留已提交数据 |
| 运行重试 | 新建关联运行，仅重试失败部分 |
| 设置布局 | 左侧栏目导航 |
| Tag 模块 | 尚未设计完成，当前暂停 |
| 设计系统 | Stamen Atlas 已最终定稿，具体规则以 `docs/design.md` 为准 |
