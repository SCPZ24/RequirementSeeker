# ADR-001：Agent M0 工程底座与契约边界

- 日期：2026-09-05。
- 状态：随用户授权推进 M0，在 Agent 模块范围采用；不决定整个产品的技术栈。
- 对应实现：[packages/agent](../../packages/agent/)。

## 决定与原因

Agent 以独立 Python 库和版本化 JSON 接入，M0 不建立服务进程。Python 类型模型与 JSON Schema 共用一份定义，便于后续采集和宿主使用不同技术栈。相比先选定整个 Web 后端，模块级选择不要求发起者提前完成产品基础设施；相比只交 JSON 文档，可执行验证能及时发现接口错误。

工具链采用 Python 3.12.10、uv 0.11.7、Pydantic 2。测试使用 pytest 与 jsonschema，Lint/格式化使用 Ruff，类型检查使用 mypy strict，构建使用 Hatchling 1.32.0。当前受支持 Python 范围限定为 `>=3.12,<3.13`；增加解释器版本需先验证，不暗示只在 Windows 可运行。

首次解析的直接依赖为 Pydantic 2.13.5、pytest 9.1.1、jsonschema 4.26.0、Ruff 0.16.6、mypy 1.20.2。精确运行/开发依赖及哈希记录在 `packages/agent/uv.lock`；构建后端单独固定。uv 的跨平台锁文件不等于已经完成 macOS 测试。

采用 [Pydantic 的严格字段验证](https://docs.pydantic.dev/latest/concepts/strict_mode/) 约束数字和布尔类型；时间字段显式接受带时区 RFC3339 字符串。由模型直接 [生成 JSON Schema](https://docs.pydantic.dev/latest/concepts/json_schema/)，测试防止导出文件漂移。安装与锁文件流程依据 [uv 项目文档](https://docs.astral.sh/uv/guides/projects/)。

## 模块与宿主职责

- Agent 拥有 `AnalysisRequest`、`AnalysisResult` 和领域结果 Schema；宿主负责生产/消费它们。
- Agent 返回候选或合并意图，宿主拥有正式机会 ID、入库事务、唯一约束、生命周期、人工资料与提交时间。
- 作者 ID 在短期输入中可以是稳定平台 ID 或宿主提供的稳定匿名标识；同一安装、同一平台需保持一致。缺失值用 `null`，不得编造随机用户 ID。
- M1 的准入实现必须根据可信输入重新核对作者和引文，不信任模型声称的证据；视频作者身份未知时不得假设已成功排除作者本人。
- 长期匿名标识建议由宿主管理安装级秘密，按平台和稳定作者 ID 计算 HMAC；密钥、迁移及实际实现归宿主后续接入，不在 M0 添加密码学或存储代码。
- 媒体字段只携带内容或不透明引用，M0 不解析引用为路径、不下载文件。生产媒体访问授权、类型/大小校验由媒体适配器负责。
- 目前仅交付契约；ModelGateway、历史检索、存储和提交接口的生产实现属于 M2–M6。

## 时间与保留期

M0 采用首次采集时刻作为普通评论保留期起点：`expires_at = first_collected_at + 10 × 24 小时`。所有时间归一化到 UTC，不使用机器当前时间隐式判定。

请求必须满足 `first_collected_at <= analysis_time < expires_at`。到期时刻本身已经过期；重复抓取不更改首次采集时间。请求包含单视频完整有效快照，调用方在进入 Agent 前组装跨日评论；M0 拒绝过期或重复 ID 快照，M1 再实现标准化和预处理能力。

媒体中间结果允许更短期限，不能超过自身首次采集后的十天；生产适配器还必须把期限限制在来源原始材料的最早到期时刻。M0 不实现删除任务，不将契约验证冒充物理清理。

正式机会证据、长期审计元数据和普通原文分层保存。原始模型输入输出、未选证据和媒体正文仍受原始数据期限约束；M0 模型审计类型没有请求/响应正文或密钥字段。

## 重放与恢复语义

后续稳定分析键应由规范化输入快照内容、规则版本、提示词版本、Schema 版本、模型配置及可获取的供应商模型版本、相关历史版本构成。运行 ID、快照记录 ID 和当前机器时间不应单独破坏幂等性。

快照里的有效成员变化应改变键；同一有效输入、同一依赖版本重用已校验模型结果。模型版本不可获取时记录 `revision=null`，不承诺新发起远程推理天然可重复。缓存过期后不能重放普通正文，应建立新的合法输入和分析记录。

`idempotency_key` 在 M0 只验证为 64 位小写十六进制，不实现键计算或去重。M4 实现时：新建键基于规范化候选来源，合并键还包含目标机会与证据集合；重试产生新的运行 ID，用 `retry_of_run_id` 关联，不能将新运行指向自身。

## 有限预算与重试默认值

这些值是单视频分析请求的模块默认上限，不是 PRD 的整个探测任务预算：

| 参数 | 默认值 | 语义 |
|---|---:|---|
| `max_comments` | 200 | 调用方提交的有效快照条数上限，可配置 |
| `max_model_calls` | 8 | 包括首次、修复及网络重试在内的实际调用上限 |
| `max_input_tokens` | 16000 | 单视频累计输入额度 |
| `max_output_tokens` | 4000 | 单视频累计输出额度 |
| `max_transport_retries` | 2 | 首次请求之外的网络重试次数，配置范围 0–5 |
| `max_output_repairs` | 1 | 结构化输出修复次数，配置范围 0–2 |

模型调用及 Token 额度允许设为零，表示禁止相应消费。最终实际调用量受所有上限共同约束，不能因为每步都允许重试就突破总额度。

M2 实现预算预留与结算：发送前保守估算输入并预留最大输出，响应后按可得 usage 结算；供应商不返回 usage 时保留未知状态及保守预留，不能计为真实零消费。硬性 Token 上限能否精确实施还依赖具体模型的计数/最大输出能力，须在真实模型接入时验证。

M0 只校验配置合法和快照条数，不消耗或结算预算。阶段错误、业务拒绝、上下文不足、预算结束、取消具有不同结果类型。

## 版本、兼容与测试边界

线协议为 `schema_version="1.0"`，包版本为 `0.1.0`。所有对象拒绝额外字段，错误版本立即失败；消费者不应假设新增字段可被旧版本忽略。破坏性变更需显式新契约版本与样本，双方接入时迁移；修正说明或不改变合法负载集合的代码修复可保持版本。

JSON Schema 验证字段结构，Python 校验器另行验证字段间关系，例如到期窗口、证据作者唯一性和视频归属。通过 Schema 不代表完成这些关系校验，更不代表通过语义准入。

M0 的合成业务预期是未来评测种子，不是运行模型获得的结果。当前只验收结构合法性、错误出口、类型、格式、构建与离线安装；H0/H1 仍未完成。
